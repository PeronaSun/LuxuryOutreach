# Reliability diagnosis before implementation

Inspected commit: `ebd1ca7` (clean working tree at task start). This document records code evidence, not a claim that every observed user failure has the same cause.

| Code path                                   | Finding and consequence                                                                                                                                                                                                                                                                                           |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server/rules.mjs::resolveProduct`          | `productScenarios` includes recommendations, reactivation, events and price. All four rank the full/current catalog and return a SKU even when the scenario needs only a greeting, invitation or broad story. No explicit distinction between unselected and not applicable exists.                               |
| `evaluateRequest`, price branch             | An unselected SKU is rejected instead of allowing a general price discussion without invented specifications.                                                                                                                                                                                                     |
| `message-contract.mjs::storyFor`            | A story exists only if a SKU exists. Selected Motif/Line context is therefore conflated with a product recommendation.                                                                                                                                                                                            |
| `generation.mjs::buildPrompt`               | Global style/story instructions require SKU details and Motif→Line→SKU storytelling, competing with non-product scenario instructions. A fixed 1,800-token budget, no explicit sampling configuration and categorical output rules can yield differing outcomes across calls.                                     |
| `candidateSchemaFor` / `assembleCandidates` | The provider must return exact CTA pool strings, three candidates in a fixed order, and no unexpected fields. Safe whitespace normalization exists, but valid alternative restrained CTA wording is treated as a format error.                                                                                    |
| `validateMessage`                           | Series-name matching treats every series other than the resolved SKU's series as wrong, even when no SKU is required. Gemstone checks match words rather than assertions (e.g. “不含钻石” can be flagged on a gem-free bracelet). Correct internal SKU identifiers are not prevented from reaching customer text. |
| `generate`                                  | Each request makes at most one generation and one audit. Parse/schema/factual failures terminate immediately. There is no backoff, constrained repair or configurable recovery budget.                                                                                                                            |
| `generation-errors.mjs::diagnosticEvent`    | Retry count is hardcoded to zero; selection depth, resolved scope and completion details are absent. Console diagnostics are opt-in; failures lack a separate always-recorded safe stage trace.                                                                                                                   |
| `src/main.jsx` validation effect            | Aborts obsolete checks but installs results with `.then(setValidation)` without checking request identity. Generation results already compare a revision, but synchronous duplicate submissions rely on React state rather than a ref lock.                                                                       |
| `scripts/evaluate.mjs`                      | Live execution is OpenAI-key-gated and overwrites fixed historical output paths. It is unsuitable as the new DeepSeek reliability runner. Frozen evaluation files must remain untouched.                                                                                                                          |

All 15 canonical catalog records share a consistent schema and have source-backed material, category, description and price. Their gemstone field can legitimately be null. No evidence warrants changing catalog or client history data. The recorded previous successful DeepSeek calls establish connectivity, not stochastic success rates across all scenarios.

Implementation will retain canonical facts and hard audit gates, introduce normalized scope-aware context, support non-product tasks without forced SKU resolution, use typed bounded recovery, preserve safe warnings, and record new runs separately. Broad regression uses deterministic mocks. The small live sample is capped at eight application generations and 24 provider calls globally; no large paid evaluation is authorized or planned.
